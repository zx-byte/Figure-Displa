# 拾光手办 · 微信小程序

> **当前运行模式：纯展示**
> 不依赖云开发、不产生月费、不需要营业执照，可直接提交审核上线。
> 开关位于 `miniprogram/config/constants.js`：`DEMO_MODE = true`、`SHOW_TRADE = false`。
> 切换为完整电商模式的方式见文末附录。

面向个人手作工作室的作品展示与定制咨询小程序，三条业务线为**现货展示 / 限量发售 / 专属定制**。  
技术栈：WXML + WXSS + JavaScript 原生开发，后端使用微信云开发（云函数 + 云数据库 + 云存储），无需任何独立服务器。纯展示模式下不触达后端。

配套文档：`docs/自制手办商城小程序_需求分析与开发计划书_v1.0.docx`
（该文档编制于立项阶段，当时项目暂名「自制手办商城」；正式名称已定为「拾光手办」，技术方案与业务口径均未变化。）

## 一、前置条件（缺一不可）

本节三项是硬性门槛，未满足时项目无法上线，与代码质量无关。

| 事项     | 要求          | 说明                           |
| ------ | ----------- | ---------------------------- |
| 经营主体   | 个体工商户或企业    | 微信支付**不对个人主体开放**，无执照无法接入交易闭环 |
| 小程序认证  | 已完成微信认证     | 未认证无法开通微信支付、客服等能力            |
| ICP 备案 | 已完成小程序备案    | 2023 年起强制，平台审核约 1 至 20 个工作日  |
| 服务类目   | 电商平台 / 商家自营 | 营业执照经营范围需含「工艺美术品销售」或「玩具销售」   |



> 主体注册与备案建议与开发并行推进，这两项构成了工期的关键路径。

## 二、导入项目

1. 打开微信开发者工具，选择「导入项目」。
2. 目录选择本仓库根目录（含 `project.config.json` 的那一层）。
3. AppID 填写你自己的小程序 AppID（`project.config.json` 中的 `touristappid` 为占位值，导入后会自动替换）。
4. 基础库版本选择 **2.25.0 或以上**。

导入后目录结构如下：

```
.
├── miniprogram/            小程序前端
│   ├── app.js              云开发初始化、静默登录
│   ├── app.json            页面注册、tabBar
│   ├── app.wxss            设计令牌与全局样式
│   ├── config/constants.js 状态映射、筛选维度、运费规则
│   ├── utils/              cloud / format / validate / toast / admin
│   ├── components/         goods-card / empty-state / loading-view / section-header / before-after / panorama / privacy-modal
│   ├── images/tabbar/      8 个 tabBar 图标（4 组 × 普通/选中）
│   └── pages/              26 个页面（买家端 20 + 商家端 6）
├── cloudfunctions/         11 个云函数（10 个业务 + 1 个初始化工具）
├── docs/                   需求文档 + preview.html 视觉预览
├── scripts/                图标生成、结构检查、接口检查
```

### 视觉预览

`docs/preview.html` 用浏览器打开即可看到首页、详情、购物车、确认订单、个人中心、经营概览六个页面的实际视觉，按 WXSS 的实际尺寸换算还原，右侧附每页的设计要点。

## 三、开通云开发

1. 开发者工具顶部点击「云开发」，新建环境（建议选择**广州**地域，云函数时区与国内一致，影响「今日销售额」的统计边界）。
2. 记下环境 ID。若使用默认环境可不填；多环境时把环境 ID 写入 `miniprogram/config/constants.js` 的 `CLOUD_ENV`。
3. 云开发控制台 → 设置 → 权限设置：确保已开通云数据库、云存储、云函数。

## 四、部署云函数

### 4.1 逐个上传

在开发者工具左侧 `cloudfunctions` 目录下，对每个子目录右键 →「上传并部署：云端安装依赖」。

九个业务函数：`login`、`product`、`order`、`pay`、`custom`、`address`、`favorite`、`admin`、`stats`
一个合规函数：`security`（内容安全检测，见第七章）
一个工具函数：`initdb`

> `security` 与 `custom` 带 `config.json`，声明了 openapi 权限。部署时用「上传并部署：云端安装依赖」，
> 只覆盖 `index.js` 不会更新权限声明，内容检测会报 `-604101 无权限`。

### 4.2 环境变量（关键，配置错则无法运行）

云开发控制台 → 云函数 → 选中函数 → 配置 → 环境变量。**以下变量需要在多个函数中分别配置，且值必须一致**：

| 变量名              | 需配置的函数                  | 说明                            |
| ---------------- | ----------------------- | ----------------------------- |
| `ADMIN_OPENIDS`  | `login`、`admin`、`stats` | 管理员 openid，多个用英文逗号分隔。三处必须完全一致 |
| `ADMIN_PASSWORD` | `admin`                 | 管理后台登录口令，建议 8 位以上             |
| `ADMIN_SECRET`   | `admin`、`stats`         | 令牌签名密钥，两处必须一致，建议 32 位随机串      |
| `PAY_SUB_MCH_ID` | `pay`                   | 微信支付商户号                       |
| `INIT_TOKEN`     | `initdb`                | 初始化口令，任意随机串，初始化后删除该函数         |

> 获取自己的 openid：首次运行小程序后，在「云开发 → 数据库 → users」中查看刚生成的记录，`openid` 字段即所需值。

### 4.3 订单超时关单触发器

`order` 函数已内置 `config.json`，声明每 5 分钟扫描一次超时未支付订单。  
上传该函数后，在云开发控制台 → 云函数 → order → 触发器，确认 `closeExpiredOrders` 已创建。  
未创建时手动新建：Cron 表达式 `0 */5 * * * * *`，触发方式选 Timer。

## 五、数据库初始化

### 5.1 执行初始化

在云开发控制台 → 云函数 → `initdb` → 测试，传入：

```json
{ "action": "init", "initToken": "你在环境变量里设置的值" }
```

返回结果会列出四个集合的创建状态与示例商品写入情况。示例商品写入后没有图片，需到商家端补图。

### 5.2 集合权限（务必逐一设置）

| 集合             | 权限            | 理由              |
| -------------- | ------------- | --------------- |
| `products`     | 所有用户可读，仅管理端可写 | 商品需被所有访客读取      |
| `orders`       | 仅创建者可读写       | 订单含收货地址，不可被他人读取 |
| `users`        | 仅创建者可读写       | 含手机号与地址簿        |
| `customOrders` | 仅创建者可读写       | 含联系方式与定制需求      |

> **不要使用「所有用户可读写」**。所有写操作都已收口到云函数，云函数使用管理员权限绕过该限制，因此前端无需写权限。

### 5.3 索引（影响查询性能与数据唯一性）

在「数据库 → 索引管理」中逐个添加：

| 集合             | 索引字段                    | 类型                          | 用途             |
| -------------- | ----------------------- | --------------------------- | -------------- |
| `orders`       | `orderNo`               | 唯一                          | 支付回调按单号定位订单    |
| `orders`       | `userId` + `createTime` | 复合（userId 升序、createTime 降序） | 用户订单列表         |
| `users`        | `openid`                | 唯一                          | 登录时定位用户，杜绝重复用户 |
| `customOrders` | `orderNo`               | 唯一                          | 支付回调按单号定位定制单   |
| `customOrders` | `userId` + `createTime` | 复合                          | 定制单列表          |
| `products`     | `status` + `sort`       | 复合                          | 首页与列表排序        |

> `orderNo` 与 `openid` 的唯一索引是数据正确性的最后一道防线，建议在首次真实交易前建好。

## 六、支付配置

1. 微信商户平台申请商户号（需已认证的小程序主体）。
2. 小程序后台 → 功能 → 微信支付 → 关联商户号，完成授权。
3. 云开发控制台 → 设置 → 其他设置 → 微信支付配置，绑定商户号。
4. 把商户号填入 `pay` 云函数的环境变量 `PAY_SUB_MCH_ID`。

`pay` 云函数使用云开发原生支付 `cloud.cloudPay.unifiedOrder`，**无需上传 API 证书**，回调由微信直接调用 `pay` 云函数自身处理。

### 支付链路的三重保障

| 环节  | 机制                         | 解决的问题          |
| --- | -------------------------- | -------------- |
| 下单前 | 云函数按数据库现值重算金额，与前端提交值不符即拒绝  | 价格篡改           |
| 回调时 | 以「订单号 + 交易号」幂等，已支付订单直接返回成功 | 回调重复投递导致重复发货   |
| 支付后 | 前端主动调用 `queryOrder` 向微信侧核对 | 回调延迟或丢失导致状态不同步 |

## 七、隐私合规配置

这一节是审核硬门槛。不配置的话，隐私相关接口会被微信直接拒绝，跟代码写得好不好无关。

### 7.1 公众平台填报用户隐私保护指引

微信公众平台 → 设置 → 服务内容声明 → 用户隐私保护指引，按本项目**实际收集**的信息逐项勾选：

| 信息类型          | 对应功能                        | 是否必须    |
| ------------- | --------------------------- | ------- |
| 微信昵称、头像       | 个人中心编辑资料                    | 是       |
| 选中的照片或视频信息    | 定制需求上传参考图、更换头像              | 是       |
| 手机号           | 定制预约中用户手填的联系电话（不是微信快捷手机号）   | 否，手填不涉及 |
| 收货地址          | 开通在线交易后用于发货                 | 开启交易时必填 |

漏勾的项对应接口会被拒。例如漏了「选中的照片」，定制页 `wx.chooseMedia` 会报
`chooseMedia:fail api scope is not declared in the privacy agreement`。

> 本项目不使用 `wx.getUserProfile`，昵称头像走的是「头像昵称填写能力」
> （`open-type="chooseAvatar"` + `type="nickname"`），填报时按此说明，不要选「用户信息（昵称、头像）」以外的项。

### 7.2 小程序内的协议入口（已内置）

- `pages/privacy/privacy` — 隐私政策与用户协议双文档，顶部 tab 切换
- 入口共四处：个人中心菜单、关于页底部、定制提交页底部声明、首启弹窗内的链接
- 首次进入首页或「我的」时弹确认框，同意后写入本地 `fd_privacy_agreed`
- 拒绝不做强制退出（审核不允许），只提示功能受限，本次会话不再重复弹

条款实质性修订后要让老用户重新确认：在 `config/constants.js` 里把 `PRIVACY_VERSION` 加一即可，
本地存的旧版本号不匹配就会重新弹窗。

### 7.3 内容安全检测

新增 `security` 云函数，前端提交前调用一次，`custom.submit` 内还有一次服务端兜底。

| 场景          | 接口                      | 触发点                                   |
| ----------- | ----------------------- | ------------------------------------- |
| 定制角色描述与特殊要求 | `security.msgSecCheck` v2 | 定制页提交前 + `custom.submit` 服务端          |
| 定制参考图       | `security.imgSecCheck`    | 定制页上传完成后                              |
| 用户昵称        | `security.msgSecCheck` v2 | 个人中心保存资料前                             |

三个设计取舍，改代码前先读：

1. **检测接口不可用时放行，不阻塞业务。** 未认证、未开通能力、微信侧繁忙都会导致接口报错，
   此时若一律拒绝，用户将提交不了任何内容。代码区分两种情况：明确判定违规（`suggest=risky`
   或 `errCode 87014`）→ 拒绝；接口本身不可用（`-604101`、`-1`、超时）→ 放行并打日志。
   上线后如果日志里持续出现 `[security] ... 接口异常`，说明该去后台补开能力，而不是关掉检测。
2. **图片用同步的 `imgSecCheck`，限制单图 1MB。** 超过限制的图会跳过并标记 `degraded`。
   需要更大图或更严格时换异步的 `mediaCheckAsync`，代价是要在云开发配置消息推送接收结果。
3. **文本服务端再查一次。** 前端检测只是即时反馈，直接调云函数可以绕开，所以 `custom.submit`
   在写库前会自己调一次 `msgSecCheck`。这也意味着 `custom` 函数的 `config.json` 必须声明该权限。

验证方法（演示模式下也能测）：定制页「特殊要求」里输入含 **演示违规** 四个字的文本并提交，
应弹出「需求描述包含不当内容」且表单不提交。这是 `config/mock.js` 预留的本地触发词，
用于在不写真实违规内容的前提下验证整条拦截链路。

## 九、设计说明与已知限制

### 8.1 三处刻意的业务设计

**定金属性明示。** 定制页与商品详情页均写明「定金为总价 30%，制作启动后不予退还」。定金与预付款的法律责任不同，写法模糊会在投诉场景中处于不利地位。

**限量编号与库存同事务分配。** 下单时在数据库事务内读取 `soldCount` 顺延分配编号，并写入订单商品快照 `limitNo`。限量商品每单限购 1 体，保证编号与实物一一对应。

**定制报价可后置。** 提交时按用户填写的预期预算生成定金，商家可在确认报价时调整最终报价，定金随之重算。避免「首版写死金额、后续必须重构」。

### 8.2 已知限制

| 限制        | 现状                                  | 后续处理                                                          |
| --------- | ----------------------------------- | ------------------------------------------------------------- |
| 访客数统计     | 首版以「累计用户数」替代                        | 需增加 `visits` 集合并由前端上报                                         |
| 购物车       | 存本地缓存，换设备不同步                        | 用户量上来后可迁到云端集合                                                 |
| 商家端页面     | 与买家端同一个小程序，靠口令进入                    | 如需彻底隔离，可拆为独立小程序                                               |
| 商品详情富文本   | 支持文本块 + 图片块，不支持自由排版                 | 若需富文本，可接入 editor 组件存储 Delta                                   |
| 售后流程      | 入口已留，退款需到商户平台操作                     | 接入微信支付退款 API 后可闭环                                             |
| tabBar 图标 | 已配置 4 组线性图标（普通/选中） | 需换风格时改 `scripts/gen-tabbar-icons.py` 重新生成 |
| 图片压缩      | 依赖 `wx.chooseMedia` 的 compressed 选项 | 建议上传前在服务端再压缩一次，控制 CDN 流量                                      |

### 8.3 成本相关的实现取舍

- **购物车不入库**：省去高频云函数调用，结算时由服务端重算校验，与本地存储方案安全性等价。
- **首页数据一次取回**：轮播、限量、新品三个列表由一次 `product.home` 调用返回，避免三次往返。
- **统计结果缓存 30 秒**：`stats` 函数在实例内缓存概览数据，反复刷新不会反复聚合查询。
- **图片存云存储、库里只存 fileID**：前端直接用 fileID 渲染，无需换取临时链接，少一次网络请求。

## 十一、二次开发约定

1. **金额一律以「分」为整数存储**。数据库、云函数全部用分，只在渲染时除以 100。新增涉及金额的字段时保持同一口径。
2. **用户身份只从 `cloud.getWXContext()` 取**。不要新增任何接受前端传入 `userId` / `openid` 的接口。
3. **写操作全部走云函数**。数据库权限设为「仅创建者可读写」后，前端直接写库会失败，这是刻意设计。
4. **状态流转在云函数内做白名单校验**。`order.updateOrderStatus` 只允许 `0→-1`、`2→3`、`3→4`、`4→3`，新增流转需同步修改 `allowed` 映射。
5. **样式使用 rpx，基准宽度 750rpx**；变量与函数用小驼峰，页面目录用小写英文加中划线。

## 十二、运行模式与切换

项目有两个独立开关，都放在 `miniprogram/config/constants.js`。

### 开关一：`DEMO_MODE`（数据来源）

| 值 | 数据来自 | 适用场景 |
| --- | --- | --- |
| `true` | `config/mock.js` 的本地数据，不发起任何云调用 | 云开发未开通时预览界面、演示 |
| `false` | 云函数 + 云数据库 | 真实运营 |

### 开关二：`SHOW_TRADE`（交易入口）

| 值 | 购物车 | 详情页主按钮 | 我的页面 | 适用场景 |
| --- | --- | --- | --- | --- |
| `false` | 隐藏（tabBar 3 项） | 微信咨询定制 | 无订单、无地址，定制走客服 | 未办执照、未接微信支付 |

### 当前配置

```js
const DEMO_MODE = true    // 用本地演示数据
const SHOW_TRADE = false  // 纯展示，交易走微信
```

这个组合的效果：**不需要云开发、不需要营业执照、不需要微信支付，可以直接提交审核上线**。用户看作品，感兴趣的通过微信客服联系。

### 上线前置：开通客服

纯展示形态下客服是唯一的成交路径，但它不是写代码就能生效的——必须在后台配人，漏了不会报错，只会「用户发了消息没人收到」。

| 步骤 | 位置 | 说明 |
| --- | --- | --- |
| 1 | 小程序后台 → 功能 → 客服 | 添加客服人员，填微信号，最多 100 个 |
| 2 | 客服人员微信 | 收到「小程序客服消息」通知，点进去即可回复 |
| 3 | [mpkf.weixin.qq.com](https://mpkf.weixin.qq.com/) | 电脑端客服工具，能看到全部会话；手机上用「客服小助手」小程序 |
| 4 | 客服工具 → 设置 → 接入与回复 | 打开**自动接入**，避免会话堆在「待接入」列表 |
| 5 | 客服工具 → 设置 → 会话分流 | 多人必开「客服权重」（填每人的最大接待人数）；按业务分工再开「常见问题」 |

第 4 步是多人场景的必需项。没开自动接入时，新会话只堆在「待接入」列表里，两个人都看得到也都能接，容易出现两个人同时回复、或者谁都没注意到。开启后会话被自动接入，直接落到某个客服名下。

**自动接入 ≠ 自动回复。** 它只负责「把会话派给谁」，会话进来后仍然需要人手动回复。想让用户一进来就看到回执，要在「自动回复」里配欢迎语——「常见问题分流」的关键词也是配在这一栏里。

回复窗口是**用户发消息后的 48 小时**，超时不能再主动发起。所以别攒着不回。另外用户每发一条消息，客服最多只能回 5 条，回满后要等用户再发一条才能继续回——所以答复尽量一次说清，别来回挤牙膏。

代码侧的配合：所有客服按钮都带了 `session-from`，客服工具里能直接看到这条咨询从哪来——

| 场景 | 客服端看到的来源 |
| --- | --- |
| 详情页问某件作品 | `作品·任嘉伦陆绎` |
| 列表页搜不到 | `搜索无结果·火影` |
| 筛选后无结果 | `筛选无结果·任嘉伦/Q版` |
| 收藏页为空 | `收藏为空` |
| 首页定制卡片 | `首页·定制咨询` |
| 我的 · 定制卡片 / 菜单 | `我的·定制咨询` / `我的·联系手作人` |
| 编号查询 | `编号查询·SG20260128` |
| 订单、定制单 | `订单·SG...` / `定制单·角色名` |

### 两个以上客服怎么分工

**先明确一件事：`open-type="contact"` 没有「指定客服」的能力。** 这是微信的机制，不是代码没写——所有客服按钮拉起的都是同一个会话池，谁先接入谁接待。前端唯一能传的是 `session-from`（来源标记），传不了「要谁接」。想控制分配，只能在客服工具的配置里做。

**多人场景第一件事**：电脑打开 [mpkf.weixin.qq.com](https://mpkf.weixin.qq.com/) → 设置 → 接入与回复 → 开启**自动接入**。不开的话新会话只是堆在「待接入」列表里，两个人都看得到也都能接，容易出现两个人同时回复、或者谁都没注意到。开了以后会话会被自动接入并提醒。

**按业务分工**（一个管定制、一个管合作）靠「设置 → 会话分流」，这是官方给的分流配置：

| 分流方式 | 规则 | 对纯展示形态 |
| --- | --- | --- |
| 重复来访 | 会话结束后 48 小时内再次咨询，回到上次接待的客服 | 有效，建议开 |
| 支付金额 | 近 30 天支付金额超过阈值，转给指定客服 | **无效**，展示形态没有支付 |
| 客服权重 | 填每个客服的最大接待人数，按权重自动分配 | 有效，**多人必开** |
| 常见问题 | 用户问的内容命中自动回复里的常见问题，转给对应客服 | 有效，按业务分工唯一可行的办法 |

同时开启多个时，优先级从高到低：**重复来访 → 支付金额 → 客服权重 → 常见问题**。

「常见问题分流」是唯一能按内容分流的手段：在自动回复里建两条常见问题，关键词分别设为「定制 / 工期 / 报价 / 尺寸」和「授权 / 合作 / 转载」，再各自指定优先客服。用户消息命中哪组关键词，就落到哪个人手上。

> 界面若与上述不符，说明客服工具改过版，以 mpkf.weixin.qq.com「设置」里的实际选项为准。

**开完自动接入后，三个容易踩的坑**：

| 坑 | 表现 | 处理 |
| --- | --- | --- |
| 客服还停在「离线」状态 | 收不到任何消息提醒，会话全部落到另一个人那儿 | 在「客服小助手」小程序把状态切成「在线」，退出小程序也能继续收「服务通知」 |
| 手机端不能转接 | 分错人了，在「客服小助手」里找不到转接按钮 | 转接只能在 PC 端 mpkf 做，手机端只能靠文字说明 |
| 用户点开客服页、没打字就走了 | 不会产生可回复的会话，商家端看不到这次来访 | 入口文案写清楚要问什么（例：问价 · 定制 · 工期），把用户推到发消息那一步 |

**关于 `session-from` 的一个常见误解**：它只做来源标记，不能塞客服 ID 去指定人。有人以为把 `session-from` 写成 `{"kefu":"xxx"}` 就能指定客服——那是第三方客服 SaaS 的做法，微信官方这里只按字符串透传来源，官方文档对它的描述就是「将会话来源透传到客服」。

**「不同按钮找不同客服」有两条路，都走不通当前形态**：

| 方案 | 机制 | 前置条件 | 当前可行性 |
| --- | --- | --- | --- |
| 微信客服 | `wx.openCustomerServiceChat` 传不同客服链接 | 非个人主体 + 企业微信已验证 + 与小程序同主体 | 走不通（纯展示形态不办执照） |
| 客服子商户 | `button` 加 `business-id`，每个子商户独立会话 | 小程序类目须为【电商平台】，后台「设置-接口设置」开通 | 走不通（个人主体开不了该类目） |

两者都要求企业资质，**不必为此去办执照**——按上面的会话分流配好，日常两个人接一单业务足够了。

### 切换为完整电商

三步，缺一不可：

1. 把 `SHOW_TRADE` 改为 `true`
2. 在 `app.json` 的 `tabBar.list` 中加回购物车项（位置在第 2 项之后）：

```json
{
  "pagePath": "pages/cart/cart",
  "text": "购物车",
  "iconPath": "images/tabbar/cart.png",
  "selectedIconPath": "images/tabbar/cart-active.png"
}
```

3. 云环境就绪后把 `DEMO_MODE` 改为 `false`

> 第 2 步不能漏。`SHOW_TRADE = true` 只恢复了页面内的按钮，tabBar 是 `app.json` 的静态配置，必须手工加回，否则购物车有页面但没有入口。

### 隐藏但仍保留的功能

纯展示模式下，以下页面代码完整保留，只是没有入口。切回电商模式后自动可用，无需改动：

`cart`（购物车）、`order-confirm`（确认订单）、`order-list`（订单列表）、`order-detail`（订单详情）、`address` / `address-edit`（地址管理）、`custom-apply`（定制表单）、`custom-list` / `custom-detail`（定制进度）、`admin/*`（商家后台，6 个页面）。

价格、库存、限量编号这些字段也都在，展示模式下仍在页面上呈现，只是不构成下单动作。
