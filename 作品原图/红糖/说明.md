# 红糖作品导入说明

从已获授权的小红书主页（博主「红糖」）下载作品图，按下面三步放进小程序。

## 一、图片命名

文件名前缀就是作品名，后缀数字表示第几张图。脚本靠这个规则自动分组：

```
白老板-01.jpg     ← 作品「白老板」的第 1 张
白老板-02.jpg     ← 作品「白老板」的第 2 张
散兵.jpg          ← 作品「散兵」，单张
```

### 小红书下载的文件怎么处理

小红书网页版保存下来的文件名形如 `_1_红糖_来自小红书网页版 (3).jpg`，既没有作品名，括号和空格还会让分组错乱。这类图先整理一遍：

1. 把同名作品的图挑选出来，按 `作品名-01.jpg`、`作品名-02.jpg` 重命名；
2. 统一放进 `作品原图/红糖/_规范/` 子目录；
3. 压缩时把源目录指向 `_规范/`，而不是 `红糖/`。

这样原始下载文件保持原样，规范命名的副本单独一处，回看时不会混。
`_规范/` 与 `红糖/` 里的 jpg 一样不进仓库（已被 `.gitignore` 排除）。

规则细节：

- 分隔符用 `-`、`_` 或空格都行（`白老板-01` / `白老板_01` / `白老板 01` 等价）
- 末尾数字 1~3 位会被识别为序号，其余部分作为作品名
- 同一作品下的图按序号排序，序号最小的作封面
- **作品名里不要以数字结尾**（如「1/6手办」建议写成「六分之一手办」），否则数字会被当成序号

## 二、填元信息（可跳过）

打开 `作品信息.json`，在 `works` 里按文件名前缀加条目。不填也能跑，只是名称等于文件名、价格为「询价」。

```json
{
  "defaults": { "type": 0, "series": "粘土手办", "ip": "原创", "scale": "", "stock": 1 },
  "works": {
    "白老板": {
      "name": "白老板 · Nomad 建模手办",
      "subtitle": "1/6 比例，手工捏制",
      "price": 88000,
      "scale": "1/6",
      "detail": ["第一段说明。", "第二段说明。"]
    }
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `name` | 展示名称，不填用文件名前缀 |
| `subtitle` | 副标题，一行短句 |
| `price` | **单位是分**，88000 = 880 元。填 0 或不填，页面显示「询价」 |
| `originPrice` | 原价（分），只有大于 `price` 时才显示划线价 |
| `type` | 0 现货 / 1 限量预售 / 2 定制预约 |
| `series` | 系列，如「粘土手办」「原创系列」 |
| `ip` | 题材，如「原创」「原神」 |
| `scale` | 比例，如「1/6」 |
| `stock` | 库存，纯展示形态填 1 即可 |
| `order` | 展示顺序，数字越小越靠前；不填的排在后面 |
| `detail` | 详情段落数组，每项是一段文字 |

`defaults` 是全局兜底，`works` 里的同名键会覆盖它。

## 三、执行两步

```bash
# 1. 压缩原图，输出到 miniprogram/images/works/
#    规范命名的图放在 _规范/ 里，源目录指向它
python scripts/compress-images.py 作品原图/红糖/_规范 --width 640 --quality 68

# 2. 生成商品数据，写入 miniprogram/config/works.js
node scripts/import-works.js
```

然后重新编译小程序，首页与「全部作品」即可看到。

`--width 640 --quality 68` 是按当前主包余量定下的参数，不是默认值。图片少、余量宽裕时可以回到 `--width 750 --quality 75`，画面更清晰。

## 关于体积

小程序主包上限 2MB。放入红糖这批作品后主包约 **1.53MB，余量约 478KB**。

小红书这类照片细节密集、背景杂乱，压缩率比纯色背景的产品图低：

| 规格 | 单张体积 | 12 张合计 |
| --- | --- | --- |
| 750px / q75 | 49~107KB（平均 78KB） | 942KB，主包超 2MB |
| 640px / q68 | 34~76KB（平均 55KB） | 664KB，主包 1.53MB |

**按 55KB/张算，余量大约还能再放 8 张。** 作品继续增加时：

- 每件作品收敛到 2~3 张（封面 + 细节 + 场景），制作过程图只在有故事性时保留
- 降到 `--width 560 --quality 62`，单张约 40KB
- 或改走云存储：图片上传云开发存储，`works.js` 里存 fileID，主包就不占图片体积（容量上限变成 2GB，且不再受主包限制）

当前 4 件作品的图片张数：蓝发少年 7 张、敖丙 3 张、龙首 1 张、古风头像 1 张。

## 常见问题

**导入后小程序里没变化？**
`works.js` 是编译期读取的数据文件，需要在开发者工具里重新编译（Ctrl+B）。

**提示「作品信息.json 解析失败」？**
JSON 不支持注释和尾随逗号，中文引号（""）也不行，要用英文双引号。

**提示「这些键没有对应图片」？**
`works` 里的键和文件名前缀对不上，检查是否有空格或全角字符。
