# 红糖作品导入说明

从已获授权的小红书主页（博主「红糖」）下载作品图，用「作品工作室」上架到小程序。

## 一、日常最简流程（推荐）

```bash
# 1. 把新下载的图丢进这个目录，文件名不用改
作品原图/红糖/

# 2. 启动工作室（或直接双击项目根目录的「启动作品工作室.bat」）
node scripts/studio.js
```

浏览器会自动打开工作台，之后全在界面上完成：

1. **左栏**列出所有作品。上次分好的 27 件原样保留，新下载的图排在下面，标着「新」。
2. 新图会**按小红书笔记标题自动预分组**——同一篇笔记的图自动归到一起，你只需要核对名称对不对。
3. 把图拖到左栏任意作品上即可改归属；点图片左上角的圆圈决定**这张图要不要展示**。
4. 顶部两条进度：**主包**（代码 + 每件一张缩略图）和**分包**（详情大图）。主包满了加作品会变红，分包满了会提示还能放几张。
5. 点「生成并上架」，自动完成规范命名、双规格压缩、按预算装箱、写 `works.js`、三项自检。
6. 微信开发者工具里重新编译（Ctrl+B）。

分组结果存在 `作品原图/红糖/_分组记录.json`，下次打开直接还原，不用重复整理。

### 图片放在哪、为什么这么放

微信小程序主包只有 2MB，作品图全塞进去必然要压到糊。所以图分两套、放两个位置：

| 用途 | 位置 | 规格 | 占谁的额度 |
| --- | --- | --- | --- |
| 列表卡片封面 | `miniprogram/images/works-thumb/` | 480px WebP q74 | 主包 2MB |
| 详情页大图 | `miniprogram/subpackages/works/images/` | 1000px WebP q78 | **分包 2MB（独立额度）** |

详情页本身也在分包里（`subpackages/works/pages/detail/`）。主包访问不到分包内的图，所以列表只能用 `cover`；详情页两者都能访问。

这样主包只剩代码和缩略图，加多少作品都不会挤爆主包。分包 2MB 满了才需要减少每件作品的图片数。

### 小红书文件名不用管了

下载下来的文件名形如 `_1_红糖_来自小红书网页版 (3).jpg`，不含作品名，以前必须人工重命名。现在工作室只把它当唯一标识，作品名由你在界面上填。

笔记标题能提取出来时（如 `搓个小手办玩_1_红糖_…`），会作为作品名的初始值；提取不出来的（35 张无标题笔记）统一进「未分组」，你从里面拖图分组即可。

## 二、云存储模式（放全部 130 张）

分包虽然是独立额度，但同样只有 2MB，本地模式最多放约 34 张 1000px 的图。要展示全部 130 张就切云存储：

1. 勾选底部「云存储模式（全量，不限张数）」，生成。
2. 图片输出到 `output/cloud-batch/`，共 130 张、约 3.3MB。
3. 微信开发者工具 → **云开发 → 存储** → 新建 `works` 目录 → 把 `output/cloud-batch/` 里的图全部拖进去上传。
4. 上传后在存储里点开任意一张，复制完整 fileID（形如 `cloud://环境ID.存储桶/works/xxx.jpg`），取其目录部分 `cloud://环境ID.存储桶/works/` 填到 `output/cloud-works.js` 的 `IMG_BASE`。
5. 把 `output/cloud-works.js` 覆盖到 `miniprogram/config/works.js`。

此后主包只留代码，图片走云存储，容量上限变成 2GB 且不受主包限制。

## 三、命令行方式（不开浏览器时）

分组记录已经是现成的，纯命令行一条命令即可：

```bash
node scripts/build-works.js
```

压缩、装箱、分发、生成数据、体积报告一次跑完。常用参数：

```bash
node scripts/build-works.js --budget 1800              # 分包图片预算（KB），默认 1900
node scripts/build-works.js --detail 900 --detail-q 74 # 详情图规格，装不下时降档
node scripts/build-works.js --thumb 440 --thumb-q 72   # 缩略图规格，主包紧张时降档
```

压缩有缓存：规格没变、原图没动过的会跳过，第二次跑通常几秒完成。

只重建数据、不重新压缩：`node scripts/import-works.js`

### 命名规则（仅在手工整理 `_规范/` 时需要）

```
白老板-01.jpg     ← 作品「白老板」的第 1 张
白老板-02.jpg     ← 作品「白老板」的第 2 张
散兵.jpg          ← 作品「散兵」，单张
```

- 分隔符 `-`、`_`、空格都行
- 末尾 1~3 位数字是序号，其余部分是作品名，序号最小的作封面
- **作品名不要以数字结尾**（「1/6手办」应写成「六分之一手办」），否则数字会被当成序号

## 四、作品元信息

`作品信息.json` 的 `works` 里按作品名加条目。工作室只会自动同步 `order` 和 `name`，其余文案手工维护。不填也能跑，只是价格为「询价」。

```json
{
  "defaults": { "type": 0, "series": "粘土手办", "ip": "原创", "scale": "", "stock": 1 },
  "works": {
    "白老板": {
      "order": 1,
      "name": "白老板 · Nomad 建模手办",
      "subtitle": "1/6 比例，手工捏制",
      "price": 88000,
      "detail": ["第一段说明。", "第二段说明。"]
    }
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `name` | 展示名称，不填则用作品名 |
| `subtitle` | 副标题，一行短句 |
| `price` | **单位是分**，88000 = 880 元。填 0 或不填，页面显示「询价」 |
| `originPrice` | 原价（分），大于 `price` 时才显示划线价 |
| `type` | 0 现货 / 1 限量预售 / 2 定制预约 |
| `series` / `ip` / `scale` | 系列 / 题材 / 比例 |
| `ipDetail` | 题材下的具体选题（剧名、作品名）。`ip` 是固定枚举，选题细节写这里，搜索能命中 |
| `stock` | 库存，纯展示形态填 1 即可 |
| `order` | 展示顺序，由工作室自动写入，数字越小越靠前 |
| `detail` | 详情段落数组 |

`series` 与 `ip` 的取值不是随手写的，首页四个快捷入口和分类页的筛选项都按固定值匹配。
填了清单之外的值，作品在分类页里筛不出来，首页入口也点不进它。

| 字段 | 可选值 |
| --- | --- |
| `series` | `粘土手办` / `制作记录` |
| `ip` | `原创` / `任嘉伦` / `动漫游戏` / `制作过程` |

新增分类时，同步改 `miniprogram/config/constants.js` 的 `CATEGORY_DIMENSIONS`
和首页 `pages/index/index.js` 的 `QUICK_ENTRIES`，否则筛选面板里选不到。

## 五、体积约束

主包和分包各有 2MB 独立额度，两边分开算：

| 项目 | 数值 |
| --- | --- |
| 全量原图 | 130 张 / 25.7MB |
| 主包：代码 + 界面图 | 895KB（这部分不随作品变化） |
| 主包：列表缩略图 | 27 张 / 528KB，平均 20KB/张 |
| **主包合计** | **1.39MB / 2MB，余 627KB** |
| 分包：详情页四件套 | 41KB |
| 分包：详情大图 | 34 张 / 1.85MB，平均 56KB/张 |
| **分包合计** | **1.89MB / 2MB，余 110KB** |

34 张 = 27 件作品各 1 张封面 + 7 件按勾选顺序各加 1 张。分包预算还差一点放不下第 35 张。

**和改造前对比：**

| | 改造前 | 现在 |
| --- | --- | --- |
| 主包 | 1.94MB（余 63KB） | **1.39MB（余 627KB）** |
| 列表图 | 460px JPEG q64 | 480px **WebP** q74 |
| 详情图 | 460px JPEG q64 | **1000px WebP q78** |
| 详情图张数 | 39 张 | 34 张 |

主包腾出 564KB，同时详情图分辨率翻了一倍多（460 → 1000px）。WebP 同画质比 JPEG 小 25~35%，所以分辨率上去了体积反而没翻天。

**还想放更多图时：**
- 分包已经 95%，唯一办法是降规格：`--detail 900 --detail-q 74`，单张从 56KB 降到约 45KB，能多放 6 张左右
- 或者减少每件作品的图片数，把预算留给重点作品
- 或者上云存储，130 张全量，不受 2MB 约束

## 八、常见问题

**双击 bat 闪退？**
看命令行窗口的报错。多半是没装 Node.js，或 Python 缺 Pillow（`pip install Pillow`）。

**工作室里改了名，小程序没变？**
点「生成并上架」才会写入 `works.js`；之后再在开发者工具里编译（Ctrl+B）。

**导入后小程序里没变化？**
`works.js` 是编译期读取的数据文件，必须重新编译。

**提示「作品信息.json 解析失败」？**
JSON 不支持注释和尾随逗号，中文引号（""）也不行，要用英文双引号。

**为什么列表里只剩下真实作品，演示商品不见了？**
`mock.js` 按 `WORKS.length` 判断：有真实作品就只用真实作品，没有才用演示数据撑页面。

**缩略图显示不出来？**
工作室启动时会用 Python 生成缩略图到 `output/_studio/thumbs/`。缺图时点界面上的「刷新」，或手动跑 `python scripts/studio-thumbs.py --force`。
