### 抓取能力边界（重要，后续别再白试）
- 小红书主页静态抓取只能拿到文字（昵称/笔记标题/点赞数），**拿不到封面图地址**——
  必须登录态，curl 会被 302 到登录页。
- 本机无浏览器控制扩展（Chrome Extensions 目录为空），无法自动化带登录态取图。
- 连接器市场无「指定博主主页取图」能力（只有选品/舆情/设计类）。
- 结论：图片必须用户手动下载提供。

### 新增能力
- `scripts/import-works.js`：扫描 `miniprogram/images/works/`，按文件名前缀分组为作品，
  读 `作品原图/红糖/作品信息.json` 元信息，生成 `miniprogram/config/works.js`，
  并输出 `output/works-seed.json`（云数据库上线用种子）。
- `miniprogram/config/works.js`：自动生成的作品数据模块（初始为空数组）。
- `mock.js`：`PRODUCTS = WORKS.concat([...演示商品])`，真实作品 sort 从 900 递减排最前。
- 分组规则：`作品名-01.jpg` / `作品名-02.jpg` → 同一件作品，序号最小的作封面；
  `-`/`_`/空格均可作分隔符；末尾 1~3 位数字识别为序号。
- 元信息支持 `defaults` 全局兜底 + `works` 单件覆盖；缺失时按默认值生成不报错；
  元信息键无对应图片会告警。

## 作品扩容到 27 件（同日第三轮）

用户重新下载了完整作品集，`作品原图/红糖/` 从 12 张涨到 **130 张**（23 篇笔记）。

### 小红书批量下载的命名陷阱（关键经验）
文件名形如 `{笔记标题}_{第几张}_{作者}_来自小红书网页版{ (副本n)}.jpg`：
- `_N_` 是**笔记内的第几张图**，不是第 N 件作品
- 括号 `(1)(2)(3)` 是**重名副本**，同一张图可能有多个副本，也可能不同图撞名
- 无标题笔记的 35 张全部变成 `_1_红糖…(7).jpg` 这种，**完全没有作品信息**
- 同一件作品的图会跨不同笔记标题（蓝发少年的图分散在「搓个小手办玩」和无标题组）
→ **只能靠看图归组**，文件名前缀不可信。

### 高效归组方法：contact sheet（拼图总览）
130 张逐张 Read 成本过高。做法：Pillow 拼 7 列 × 5 行缩略图，每格 250×330、
顶部黑条标编号 `#NN 标题-序号`，一张 sheet 装 35 张，3 张看完 95 张有标题的。
配合 `index.tsv`（编号 → 原文件名）就能一次性判断分组。
**这套方法值得复用**：脚本逻辑见本次 `_contact_sheet.py`（已删，需要时按此重建）。

### 归组结果：27 件 / 130 张

## 作品工作室（2026-10-27 晚）

### 动机
每次上传作品都要人工重命名 130 个乱名文件、逐张看图分组、手写 27 条元信息，
用户提出「能否设计一个简单的方式」。

### 交付
- `scripts/studio.js` — 本地服务（零依赖，默认 7788 端口，自动开浏览器）
- `scripts/studio.ui.html` — 单页界面：左栏作品列表 / 右栏缩略图网格
- `scripts/studio-thumbs.py` — 360px 缩略图，按文件名 md5 前 10 位命名
- `scripts/prune-dir.py` — 目录裁剪，Python 侧删除
- `启动作品工作室.bat` — GBK 编码 + CRLF，双击启动

### 核心设计
1. **增量识别**：`作品原图/红糖/_分组记录.json` 存「原文件名 → 作品名」，
   已确认的组原样还原，只有新图进待处理区。
2. **预分组**：从小红书文件名 `{笔记标题}_{序号}_{博主}_来自小红书` 提取标题自动归组；
   无标题的（35 张那种）统一进「未分组」，人工拖拽拆分。
3. **picked 语义**：记录用户真实勾选，云模式只在压缩时忽略它。
   （踩过坑：早期把「全量」写进记录，切回本地模式就误压 130 张、主包 4.22MB）

### 踩坑记录（重要）
- **Node `fs.unlinkSync` 在本机偶发 EBUSY**，刚写完的图片尤其明显；
  重试 3 次也救不回来。最终把删除整体交给 `prune-dir.py`（Python `os.remove` 稳定）。
- `fs.rmSync(recursive)` 触发环境批量删除保护（>50 文件），一律不用。
- Python 在 Windows 控制台输出 GBK，解析中文日志要设 `PYTHONIOENCODING=utf-8`。
- 迁移脚本用 MD5 反推 `_规范/` 与原图的对应关系（130/130 全命中），
  据此生成首份 `_分组记录.json`，避免重做已完成的 27 件分组。
- `syncDir` 曾把 `miniprogram/images/works/.gitkeep` 一起删掉，改为跳过 `.` 开头文件。

### 云存储模式
勾选后全量压缩到 `output/cloud-batch/`（130 张 / 3.31MB），
生成 `output/cloud-works.js`：图片路径为裸文件名，顶部 `IMG_BASE` 常量待填
`cloud://<环境ID>.<存储桶>/works/`。主包不再受 2MB 限制。

### 顺带改造
- `compress-images.py` 加 `--only <清单>`：只压清单里的图，
  不再需要为了挑图复制整个临时目录（原图副本曾占几十 MB 且删不干净）
- `import-works.js` 加 `--out` / `--prefix` / `--cloud`
- `.gitattributes` 补 `*.bat text eol=crlf`

### 实测
生成耗时 29s（首次）/ 7s（幂等重跑），连续两次结果完全一致，
主包稳定 1.94MB，三项自检全过。
