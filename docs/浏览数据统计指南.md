# 浏览数据统计指南

回答一个问题：**不用云开发、不花钱，能不能看到「多少人看了、看了哪件作品」？**

能。用微信官方的数据平台，免费。

---

## 一、先说清楚一个坑

微信官方统计**只按页面路径聚合**。所有商品详情页的路径都是 `pages/detail/detail`，所以官方后台能看到「今天有 87 人次访问了详情页」，但**看不到看的是哪一件**。

这不是配置问题，是官方统计的粒度限制。微信开放社区的官方答复原文是：

> 不支持直接查看，可以自行埋点上报数据，然后在【行为分析-事件分析】里进行统计处理。

所以要做商品级统计，必须手动上报商品 ID。代码已经写好了，你只需要在后台创建对应的事件。

---

## 二、免费能拿到什么

两类数据，来源不同：

| 数据类型 | 来源 | 需要做什么 | 能看到 |
| --- | --- | --- | --- |
| **基础流量** | 官方自动采集 | 什么都不做 | 访问人数、打开次数、页面访问排行、来源渠道、留存率、用户画像 |
| **商品级行为** | 手动埋点 | 后台配置事件（一次性） | 每件作品被看了多少次、咨询转化、定制需求分布 |

基础流量数据在小程序发布后**自动就有**，不需要写一行代码。

---

## 三、开通步骤

### 1. 进入数据平台

两个入口，任选其一：

- **We分析**：`wedata.weixin.qq.com`，微信官方数据平台，用小程序管理员微信扫码登录
- **小程序后台**：`mp.weixin.qq.com` → 数据分析

We分析的基础版**免费使用**，限制是：上报额度 5,000 条/日、数据保存周期较短、仅支持查阅不支持下载。对个人工作室完全够用。

### 2. 配置自定义事件

在 We分析控制台 → 数据管理 → 事件管理（或小程序后台 → 数据分析 → 自定义分析），新建以下三个事件。

**事件名和字段名必须与代码里完全一致**，大小写敏感。

#### 事件 1：`view_product`（商品浏览）

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `product_id` | 字符串 | 商品 ID |
| `product_name` | 字符串 | 商品名称 |
| `category` | 字符串 | 系列分类 |
| `price` | 数值 | 价格（分） |

#### 事件 2：`click_consult`（咨询点击）

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `product_id` | 字符串 | 商品 ID |
| `from_page` | 字符串 | 来源位置，如 `detail-service`、`detail-custom` |

#### 事件 3：`submit_custom`（定制提交）

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `scale` | 字符串 | 作品比例 |
| `style` | 字符串 | 风格取向 |
| `budget` | 数值 | 预期预算（元） |

> 字段名写错不会报错，但数据会进不了那个字段，报表里是空的。配置完先在开发者工具里点一遍详情页，控制台会打印 `[track] view_product {...}`，确认上报的参数与后台字段对得上。

### 3. 发布后才有数据

开发版、体验版的数据**不计入正式统计**。必须是小程序已发布（或已通过审核的线上版本），埋点数据才会进入报表。

所以在正式发布前，你只能在开发者工具的 Console 里看到 `[track]` 日志，用来确认埋点触发正确。

## 四、数据在哪看

| 想看什么 | 去哪里 |
| --- | --- |
| 今天多少人来、看了几个页面 | We分析 → 平台数据看板 |
| 用户在页面之间怎么流转 | We分析 → 页面流转分析 |
| **每件作品被看了多少次** | We分析 → 行为分析 → 事件分析，选 `view_product`，按 `product_id` 分组 |
| 看了详情的人里多少人点了咨询 | 事件分析，对比 `view_product` 与 `click_consult` |
| 用户从哪来（搜一搜 / 分享 / 二维码） | We分析 → 增长归因 |

**最有用的一张表**：事件分析选 `view_product`，维度选 `product_id`，指标选「触发次数」，按次数降序。这就是你的「作品热度排行」——哪件作品最吸引人，一目了然。

---

## 五、限制与应对

| 限制 | 影响 | 怎么办 |
| --- | --- | --- |
| 上报额度 5,000 条/日 | 约支撑 1,600 次详情页浏览 | 个人工作室一天几十次访问，完全够用；超了才需要升级专业版 |
| 数据保存周期较短 | 看不到很久以前的历史 | 每周手动截个图或导个表 |
| 不能看「谁」看了什么 | 只有汇总，无个体追踪 | 这是隐私保护的必然，任何合规方案都看不到 |
| 数据延迟 | 通常次日才能看到完整数据 | 当天想看实时数据，只能看控制台的 `[track]` 日志 |

## 六、数据之外的土办法

如果觉得埋点太麻烦，还有三个不花钱的替代信号：

1. **客服咨询量**：哪件作品问的人多，就是它最受欢迎。比浏览数据更接近成交。
2. **收藏数**：详情页的收藏按钮点一下就能看，收藏是强意向信号。
3. **定制需求里的题材**：用户提交定制时填的「想要的角色」，直接反映他们想要什么。

这三个都写进了现有功能，不需要额外开发。

---

## 七、什么时候才需要自建统计

只有这些情况才值得花钱：

- 日浏览超过 1,600 次，免费额度不够
- 需要看「看了 A 又看了 B 的人有多少」这类关联分析
- 需要把浏览数据和订单数据关联（比如「看了 3 次以上的人成交率多少」）

那时候再开通云开发，把浏览记录写进数据库，想做多细的查询都行。当前的埋点代码不需要改，只是把上报目标从微信统计换成自己的集合。
