# 云开发配置指南

本文档把「从小程序代码到能真实跑起来」的配置过程按顺序拆开。每一步都能独立验证，做完一步再做下一步，出问题时能快速定位是哪一环。

预计耗时：**首次配置约 40 分钟**，其中云环境创建和依赖安装是主要等待项。

---

## 关于费用（先看这一节，再决定要不要开通）

微信云开发**从 2022 年起取消了免费额度**，新开通的环境必须选择付费套餐。这是官方政策调整，不是本项目的额外要求，也无法通过技术手段绕过。

当前开通页显示的是（以控制台实际显示为准）：

| 项目 | 内容 |
| --- | --- |
| 套餐 | 个人版 19.9 元/月（连续订阅与单月同价） |
| 配额 | 40,000 资源点/月 |
| 超限 | 可设置「超限后按量计费」 |

### 这 19.9 元买到的是什么

不是买「云开发」这个软件，是买一套不用自己运维的后端：

- 不用买服务器、不用配 Nginx、不用管系统补丁
- 不用单独申请域名和 HTTPS 证书（云开发资源走微信内部链路）
- 不用自己写接口鉴权，`getWXContext()` 直接拿到可信的 openid
- 数据库、文件存储、定时任务开箱可用

对照一下：一台最低配的云服务器年付约 100 至 300 元，还不能省掉域名备案、SSL 配置、后端运维这些事。对小体量项目，19.9 元/月的托管方案通常比自建更省事。

### 40,000 点够不够用

资源点由云函数调用、数据库读写、存储容量、CDN 流量共同消耗，其中**商品图片的 CDN 流量是主要消耗项**。

按一般电商小程序的交互密度粗估，一次「浏览首页 → 看详情 → 加购物车」大约消耗 10 到 20 点，4 万点大致对应**每月数千次访问**的量级。个人工作室起步阶段完全够用，具体折算率以控制台「资源点消耗规则」为准。

想省资源点，最有效的一招是**控制商品图体积**：上传前压到 200KB 以内，比优化代码的效果大得多。

### 什么时候可以不开通

如果当前只是想看界面和交互，**不用付费**。项目内置了演示降级机制（详见第五节），云环境未连通时会自动用本地演示数据渲染，所有页面都能正常浏览、点击、走流程，只有真实支付走不通。

等确定要接真实订单了，再开通也不迟——代码不需要任何改动。

### 容易混淆的一点：云开发费用 ≠ 微信支付

这两件事完全独立，不要混为一谈：

| | 微信支付 | 云开发套餐 |
| --- | --- | --- |
| 是什么 | 收款的通道 | 存数据、跑后端的服务器 |
| 开通成本 | 免费（需营业执照） | 19.9 元/月 |
| 使用成本 | 每笔约 0.6% 手续费 | 固定月费 |
| 不办的影响 | 收不到钱，但商品和订单照常存 | 没有任何真实数据，只能看演示 |

**不开通微信支付，并不会省掉云开发的 19.9 元。** 因为云开发收的是「服务器租金」，不是「交易抽成」——你的商品要存进数据库、订单要落库、用户要能查订单，这些都需要后端，跟你收不收钱无关。

反过来说，如果你只是做作品展示、不打算在线收款，那确实可以连微信支付都不办，但云开发这关仍然绕不过——除非连数据都不存，只做静态页面。

## 第一步：创建云开发环境

1. 开发者工具**顶部工具栏**点击「**云开发**」按钮（云朵图标）。
2. 首次点击会弹出开通页，按提示完成：
   - 选择计费方式。新用户有免费额度，具体额度以控制台当时显示的资费为准
   - 微信扫码确认开通
3. 在环境创建页填写：
   - **环境名称**：`shiguang-prod`（建议用英文，仅用于标识）
   - 环境别名：可填「拾光手办生产环境」
4. 创建完成后，在云开发控制台**顶部环境下拉框**能看到这个环境，旁边会显示**环境 ID**。

环境 ID 的格式类似 `shiguang-prod-0gk1a2b3c4d5e6`，**这串字符后面多处要用，先复制到记事本**。

> 一个 AppID 可创建的环境数量有限（免费版通常 1 至 2 个）。个人工作室建一个生产环境足够，不必另外建测试环境——需要试错时直接在数据库里改数据即可。

## 第二步：把环境 ID 写进项目

打开 `miniprogram/config/constants.js`，第 5 行：

```js
/** 云开发环境 ID。留空则使用开发者工具当前选中的默认环境 */
const CLOUD_ENV = ''
```

改成：

```js
const CLOUD_ENV = 'shiguang-prod-0gk1a2b3c4d5e6'  // 换成你自己的环境 ID
```

**为什么要显式写死**：留空时会用 `DYNAMIC_CURRENT_ENV`，即「工具里当前选中的那个环境」。开发阶段没问题，但等你以后建了第二个环境，很容易出现「代码连的是 A 环境、控制台看的是 B 环境」这种排查起来很费时间的错位。写死环境 ID 就不会有这个问题。

改完在工具里点一次「编译」，此时页面会从演示数据切换到真实的（空）数据——因为数据库还没建。这是正常现象，继续下一步。

## 第三步：部署云函数

项目共 10 个云函数，9 个业务函数加 1 个初始化工具。

### 方式一：CLI 批量部署（推荐）

服务端口已开启的情况下，在项目根目录执行：

```bash
bash scripts/deploy-functions.sh shiguang-prod-0gk1a2b3c4d5e6
```

脚本会依次部署全部 10 个函数并报告每个的结果。首次部署需要下载依赖，每个函数约 10 至 30 秒，总共 3 至 5 分钟。

### 方式二：界面手动部署

在 `cloudfunctions` 目录下，对每个函数**右键 → 上传并部署 → 云端安装依赖**。10 个函数需要操作 10 次。

> 必须选「云端安装依赖」，不能选「所有文件」。`node_modules` 有几百 MB，上传会非常慢且经常中断。

### 部署后的验证

云开发控制台 → 云函数，应该能看到 10 个函数，状态均为「正常」。

点开任意一个，在「日志」标签页应该能看到初始化记录。如果有函数显示「创建失败」，通常是依赖安装超时，重新上传一次即可。

## 第四步：配置环境变量（最容易出错的一步）

这一步的核心难点：**同一个变量要在多个函数里配相同的值**，配漏一处就会出现「买家能下单、商家进不去后台」这类诡异问题。

云开发控制台 → 云函数 → 选中函数 → **版本与配置** → 环境变量。

| 变量名 | 填什么 | 需要配置的函数 |
| --- | --- | --- |
| `INIT_TOKEN` | 任意随机串，如 `init-8f3k2j` | `initdb` |
| `ADMIN_OPENIDS` | 你的 openid，多个用英文逗号分隔 | `login`、`admin`、`stats` **（三处必须完全一致）** |
| `ADMIN_PASSWORD` | 后台登录口令，8 位以上 | `admin` |
| `ADMIN_SECRET` | 32 位随机串 | `admin`、`stats` **（两处必须一致）** |
| `PAY_SUB_MCH_ID` | 微信支付商户号 | `pay` |

### 关于 ADMIN_OPENIDS 的值

此时你还不知道自己的 openid。解决办法：

1. 先只配 `INIT_TOKEN` 和 `ADMIN_PASSWORD`、`ADMIN_SECRET`
2. 完成第五步的数据库初始化
3. 在小程序里随便点几下（会触发登录，自动在 `users` 集合创建记录）
4. 打开云开发控制台 → 数据库 → `users` 集合 → 找到刚才那条记录 → 复制 `openid` 字段
5. 回到云函数，在 `login`、`admin`、`stats` 三处填入 `ADMIN_OPENIDS`

### 关于 ADMIN_SECRET

`admin` 和 `stats` 两个函数用它做令牌签名。**两处必须填成一模一样的值**，否则会出现「后台能登录、但概览页一直提示登录过期」——因为 `stats` 用不同密钥验签失败。

**代码里没有默认值，且要求至少 16 位。** 早期版本写了一个公开的兜底串，一旦漏配就是用一个人人都知道的密钥签令牌，谁都能伪造管理员身份。现在漏配或过短会直接拒绝登录，并提示缺的是哪个变量——报错比裸奔好。

生成随机串可以用命令行：

```bash
openssl rand -hex 16
```

### 关于 PAY_SUB_MCH_ID

如果暂时没办好商户号，可以先留空。留空时点支付会提示「支付商户号未配置」，其他功能不受影响——商品、订单、定制都能正常走，只是最后一步付不了款。

## 第五步：初始化数据库

### 执行初始化

云开发控制台 → 云函数 → `initdb` → **测试** → 在参数框里填：

```json
{
  "action": "init",
  "initToken": "你在第四步给 INIT_TOKEN 设的值"
}
```

点「运行测试」，返回结果会列出四个集合的创建状态：

```json
{
  "code": 0,
  "data": {
    "collections": { "users": "created", "products": "created", ... },
    "seed": { "seeded": true, "inserted": 3 }
  }
}
```

`created` 表示新建成功，`exists` 表示已存在（正常，说明之前跑过）。

此时数据库里会有 4 个集合和 3 个示例商品。示例商品没有图片，需要到商家后台补图。

### 设置集合权限（必做）

云开发控制台 → 数据库 → 选中集合 → **权限设置**。

| 集合 | 选择哪一项 | 为什么 |
| --- | --- | --- |
| `products` | 所有用户可读，仅创建者可写 | 商品要被所有访客看到 |
| `orders` | 仅创建者可读写 | 含收货人姓名、电话、地址 |
| `users` | 仅创建者可读写 | 含手机号与地址簿 |
| `customOrders` | 仅创建者可读写 | 含联系方式与定制需求 |

> **绝对不要选「所有用户可读写」**。选了之后任何用户都能通过前端直接改写别人的订单金额。
>
> 项目所有写操作都走云函数，云函数以管理员权限运行，不受这个权限限制。所以前端不需要写权限。

### 建索引（建议在首次真实交易前完成）

数据库 → 选中集合 → 索引管理 → 添加索引。

| 集合 | 字段 | 类型 | 作用 |
| --- | --- | --- | --- |
| `users` | `openid` | 唯一 | 防止同一用户重复创建记录 |
| `orders` | `orderNo` | 唯一 | 支付回调按单号定位订单 |
| `orders` | `userId`(升序) + `createTime`(降序) | 复合 | 用户订单列表查询 |
| `customOrders` | `orderNo` | 唯一 | 支付回调按单号定位定制单 |
| `customOrders` | `userId`(升序) + `createTime`(降序) | 复合 | 定制单列表查询 |
| `products` | `status`(升序) + `sort`(降序) | 复合 | 首页与列表排序 |

`orderNo` 和 `openid` 的两个唯一索引是数据正确性的最后防线，不要跳过。

## 第六步：确认定时触发器

`cloudfunctions/order/config.json` 里已声明每 5 分钟扫描一次超时未支付订单：

```json
{
  "triggers": [
    { "name": "closeExpiredOrders", "type": "timer", "config": "0 */5 * * * * *" }
  ]
}
```

上传 `order` 函数后，到云开发控制台 → 云函数 → `order` → **触发器**标签页，确认 `closeExpiredOrders` 已存在。

如果没有，手动新建：触发方式选 Timer，Cron 表达式 `0 */5 * * * * *`。

> 没有这个触发器，用户下单后不付款，库存会被永久占用。这是必须配的一项。

## 常见问题

**Q：编译后页面全是演示数据，没有切到真实数据。**
说明云调用还在失败。检查三件事：`CLOUD_ENV` 是否填了环境 ID、云函数是否部署成功、工具底部「调试器 → Console」里有没有红色报错。演示降级只在环境类错误上触发，看到演示数据就意味着真实调用失败了。

**Q：后台登录提示「当前账号没有管理权限」。**
`ADMIN_OPENIDS` 里没有你当前的 openid。去 `users` 集合确认 openid，注意不要多复制空格。

**Q：能登录后台，但一进概览页就提示登录过期。**
`admin` 和 `stats` 两个函数的 `ADMIN_SECRET` 不一致。改成相同的值，重新上传两个函数。

**Q：支付时报「支付商户号未配置」。**
`PAY_SUB_MCH_ID` 为空。没办好商户号时这是预期行为，其他功能不受影响。

**Q：用户下单后库存一直不释放。**
`order` 函数的定时触发器没配。

**Q：图片上传成功了，但列表里不显示。**
检查 `products` 集合的权限是否为「所有用户可读」。

**Q：云函数日志里报 `Cannot find module 'wx-server-sdk'`。**
上传时选成了「上传所有文件」而不是「云端安装依赖」，重新上传。
